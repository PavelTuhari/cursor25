## Кратко

Платформа управляет SEO-продвижением произвольного числа собственных сайтов
(пилот: `una.md`, `unisim-soft`, `officeplus.md`). Вся исполнительная работа
делается автономными AI-сессиями, которые получают на вход детерминированные
Markdown-плейбуки, сгенерированные платформой. Весь финансовый и юридически
значимый документооборот (акции, бюджеты, договоры, акты, счета, платежи,
публикации) ведётся в учётной системе **UNA.md** — через интеграцию и/или ручной ввод.

```
Site Profile + данные + шаблон  →  Playbook (.md)  →  AI-сессия  →  Артефакты
                                        ↑                              ↓
                                    Git-история              Approval → Публикация
                                                                       ↓
                                              UNA.md (документы, проводки, бюджет)
                                                                       ↓
                                                              Метрики + ROI → Дашборд
```

## Исполнение сессий

Запуск встаёт в очередь (`status = queued`); раннер забирает его атомарно и
исполняет плейбук через Messages API. Лимиты из front-matter — токены, время,
число внешних вызовов — считаются в коде, а не «по договорённости» внутри
промпта: модель не может себя ограничить.

Раннер по умолчанию выключен (`RUNNER=off`) — исполнение тратит деньги.
Включается `RUNNER=claude` плюс `ANTHROPIC_API_KEY` в окружении.

### Инструменты

| Инструмент | Что делает | Нужен ключ |
|---|---|---|
| `mcp-site` | Чтение страниц, строго по `network_allowlist` плейбука | нет |
| `mcp-lang` | Румынская диакритика, длина мета-тегов, плотность ключа | нет |
| `mcp-serp` | Выдача: органический ТОП, People Also Ask, наличие AI-ответа | `SERP_API_KEY` |
| `mcp-gsc` | Search Console: запросы, показы, клики, CTR, позиции | `GSC_*` |

Коннектор без ключа **не регистрируется**, и плейбук, которому он нужен,
отклоняется с понятной причиной. Подключить наполовину означает получить
выдуманные позиции вместо реальных. Частичный прогон возможен явным согласием
(`RUNNER_ALLOW_MISSING_TOOLS=true`) — тогда недостающие инструменты
перечисляются в промпте, агент обязан помечать недоступное как `[TODO]`,
а список уезжает в `missing_tools` отчёта.

## Расписания

Cron из пяти полей, время UTC. Срабатывание генерирует плейбук и ставит запуск
в очередь — исполняет по-прежнему раннер, и только если он включён. Ошибка
одного расписания не останавливает остальные: сломанные параметры одной задачи
не повод не снять позиции по всем сайтам.

Планировщик выключен по умолчанию (`SCHEDULER=off`). Ручной прогон —
`POST /scheduler/tick`.

## Каналы и публикация

Facebook, Instagram, LinkedIn и Telegram — публикация и проверка подключений.
Как получить доступы и завести тестовые аккаунты: [`docs/CONNECTORS.md`](./docs/CONNECTORS.md).

Публикация **не является инструментом AI-сессии**. Агент готовит текст, кнопку
нажимает человек, платформа исполняет его решение. Перед отправкой в коде
проверяется три вещи, и ни одна не доверена инструкции в промпте:

| Заслон | Где настраивается |
|---|---|
| Публикация вообще разрешена | `publishing.enabled`, по умолчанию выключено |
| Материал утверждён человеком | `publishing.require_approval`; AI утверждать не может |
| Суточный лимит аккаунта не исчерпан | лимит подключения или `publishing.default_rate_limit_per_day` |

Плюс: подключение заводится в песочнице, `dry_run` прогоняет все проверки и
собирает запрос, ничего не отправляя, а публикация в статусе `published`
повторно не уходит.

Живая проверка подключений — `node scripts/check-connectors.mjs`. Обращается к
настоящим API, ничего не публикует.

## Настройки

Всё, что влияет на поведение, настраивается через панель (`/settings`) и живёт
в базе: исполнять ли очередь, какая модель, разрешена ли публикация, лимиты,
потолок расхода на токены. Значение ищется в переопределении для сайта, затем
в глобальных настройках, затем в переменной окружения, затем берётся значение
по умолчанию. Окружение ниже базы намеренно: менять поведение в бою должно быть
можно без передеплоя.

**Секреты в базе не хранятся.** В подключении лежит ссылка `env:ИМЯ` или
`vault://путь`, значение берётся из окружения. API отказывается сохранить
подключение, если секрета нет, и не отдаёт его значение наружу.

Не реализовано: коннекторы рекламных кабинетов (`mcp-ads`), шлюз `mcp-una`
для раннера, генерация проводок через `UN$GFC` (ждёт сверки интерфейса
с командой UNA — см. `db/oracle/README.md`).

## Запуск

```bash
npm install
npm run build          # движок собирается до старта API
npm test               # 202 теста: движок + API + раннер на настоящем Postgres в WASM

# Полный стек локально, без внешней базы:
DATABASE_URL=pglite UNA_MODE=mock npm run api:dev     # API на :3000
node scripts/seed-demo.mjs                            # три пилотных сайта
API_URL=http://localhost:3000 npm run web:dev         # панель на :3001
```

`DATABASE_URL=pglite` поднимает встроенный Postgres (WASM) и сам накатывает
миграции — инфраструктура для разработки не нужна. Данные живут, пока живёт
процесс. Для продакшна — настоящая строка подключения и миграции из
`db/postgres/migrations` по порядку.

`UNA_MODE=mock` поднимает шлюз-заглушку, повторяющий инварианты пакетов
`PK_SEO_*`: AI не согласует, автор не согласует сам себя, повтор по `ext_id`
не создаёт дубль, сумма документа от AI ограничена. Для продакшна нужен
`UNA_MODE=oracle` и установленный `oracledb`.

Источник структуры БД UNA:
<https://bsoft.gitbook.io/wiki/razrabotka/obekty-oracle/struktura-bazy-dannykh>
