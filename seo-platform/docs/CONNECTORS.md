# Подключение каналов и тестовые аккаунты

Платформа публикует в Facebook, Instagram, LinkedIn и Telegram. Здесь — как
получить доступы, как проверить их живой проверкой и что делать с типовыми
ошибками.

> **Порядок работы везде один.** Сначала подключение заводится в песочнице
> (`sandbox = true`), проверяется кнопкой «Проверить» или скриптом, прогоняется
> в режиме `dry_run` — и только потом переводится в боевой режим. Публикация
> необратима, откатить её нельзя.

## Проверка подключений

```bash
npm run build --workspace @seo/api
TEST_TG_CHAT=@my_test_channel TEST_TG_TOKEN=123456:AA... node scripts/check-connectors.mjs
```

Скрипт обращается к настоящим API и показывает, что именно ответила площадка.
Ничего не публикует — вызываются только методы чтения. Без учётных данных он
всё равно полезен: проверяет, что платформы достижимы и что разбор их ошибок
работает на реальных ответах.

## Telegram

Самый простой канал для первой проверки: тестовая среда встроена в Bot API.

1. Напишите [@BotFather](https://t.me/BotFather), команда `/newbot`. Получите
   токен вида `123456789:AAH...`.
2. Создайте тестовый канал, добавьте бота администратором с правом публикации.
3. Заведите подключение: `external_id` — `@имя_канала` или числовой id вида
   `-100…`, `credentials_ref` — `env:TG_TOKEN_TEST`.

Тестовая среда Telegram — это отдельный сегмент пути `/bot<токен>/test/<метод>`,
тот же хост. Подключение с `sandbox = true` уходит туда автоматически.

| Ошибка | Что значит |
|---|---|
| `401 Unauthorized` | Токен недействителен, получите новый у @BotFather |
| `404 Not Found` | Токен неверного формата: ожидается `<id>:<секрет>` |
| `403 Forbidden` | Бот не добавлен в канал или не имеет права публикации |
| `400 chat not found` | Неверный `chat_id` |

## Facebook и Instagram

Meta даёт полноценный тестовый контур: тестовое приложение, тестовые
пользователи и тестовые страницы, не видимые снаружи.

1. [developers.facebook.com](https://developers.facebook.com) → создайте
   приложение типа Business.
2. **App Roles → Test Users** — создайте тестового пользователя. Meta
   рекомендует именно их: они не затрагивают реальные страницы и аудиторию.
3. Войдя тестовым пользователем, создайте тестовую страницу.
4. Получите Page Access Token: Graph API Explorer → выберите приложение и
   страницу → разрешения `pages_manage_posts`, `pages_read_engagement`.
5. `external_id` — id страницы, `credentials_ref` — `env:FB_PAGE_TOKEN_TEST`.

Для Instagram дополнительно: Instagram Business аккаунт, связанный с тестовой
страницей, и разрешение `instagram_content_publish`. `external_id` — id
Instagram-аккаунта, не страницы Facebook.

| Код | Что значит |
|---|---|
| `190` | Токен недействителен. Для страницы нужен именно Page Access Token из `/me/accounts`, а не пользовательский |
| `200`, `10` | Не выданы разрешения на публикацию |
| `4`, `17`, `32`, `613` | Превышены лимиты платформы |
| `2500` | Запрос ушёл без токена |

Публикация в Instagram идёт в два шага: создание медиа-контейнера, затем
публикация контейнера. Без изображения Instagram пост не примет — платформа
так устроена, и коннектор сообщает об этом до обращения к API.

## LinkedIn

Отдельной песочницы у LinkedIn нет. Тестовый контур собирается так: отдельное
developer-приложение и тестовая страница компании, публикации с видимостью
`CONNECTIONS` вместо `PUBLIC`.

1. [linkedin.com/developers](https://www.linkedin.com/developers/) → создайте
   приложение, привяжите к странице компании.
2. Запросите продукт **Share on LinkedIn** (публикация от участника) либо
   **Community Management API** (публикация от организации).
3. Пройдите OAuth, получите access-токен. Он живёт 60 дней; refresh-токен
   выдаётся не всем приложениям — это ограничение платформы, планируйте
   переподключение.
4. `external_id` — id организации (станет `urn:li:organization:<id>`) либо
   готовый `urn:li:…`. Для публикации от лица человека укажите
   `config.author_type = "person"`.

Версия API передаётся заголовком `LinkedIn-Version` и обязательна: LinkedIn
версионирует API по датам и без заголовка запрос отклоняет. Версия задаётся в
`config.api_version`, по умолчанию `202509`.

| Код | Что значит |
|---|---|
| `EMPTY_ACCESS_TOKEN` | Запрос без токена: проверьте `credentials_ref` |
| `INVALID_ACCESS_TOKEN`, `EXPIRED_ACCESS_TOKEN`, `REVOKED_ACCESS_TOKEN` | Нужна повторная авторизация |
| `ACCESS_DENIED` | Приложению не выдан `w_member_social` или `w_organization_social` |
| `429` | Превышен дневной лимит приложения |

## Где живут секреты

В базе хранится только **имя** секрета (`credentials_ref`), значение берётся из
окружения или Vault. База попадает в бэкапы, реплики и логи медленных запросов —
токен публикации не должен уезжать вместе с ней.

```
credentials_ref = env:FB_PAGE_TOKEN_TEST   → переменная окружения
credentials_ref = vault://social/fb        → Vault (требует подключения VaultResolver)
```

API отказывается сохранить подключение, если секрета нет в окружении: иначе
проблема всплывёт в момент публикации, когда исправлять поздно. Значение
секрета наружу не отдаётся никогда — в списке подключений видно только имя.

## Что защищает от неприятностей

| Проверка | Где |
|---|---|
| Публикация выключена по умолчанию | `publishing.enabled` |
| Только утверждённое человеком | `publishing.require_approval`, AI утверждать не может |
| Суточный лимит на аккаунт | `rate_limit_per_day` подключения либо `publishing.default_rate_limit_per_day` |
| Повторная отправка | Публикация в статусе `published` не отправляется снова |
| Проверка до боя | `dry_run` прогоняет все проверки и собирает запрос, не отправляя его |

Публикация не является инструментом AI-сессии. Агент готовит текст и может
смотреть метрики; кнопку нажимает человек, платформа исполняет его решение.
