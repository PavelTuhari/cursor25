# UNA Market — мобильное приложение для платформы UNA.md

Кросс-платформенное (iOS + Android) розничное приложение в стиле Kaufland / Auchan:
каталог, акции и каталоги-листовки, карта лояльности со штрихкодом, список покупок,
корзина и онлайн-заказы (самовывоз и доставка), персональные купоны,
push-уведомления, сканер штрихкодов, магазины, поиск и личный кабинет
(вход по SMS-коду, профиль, история покупок и электронные чеки).

Три принципа заложены в архитектуру:

1. **Всё конфигурируется через JSON.** Бренд, тема, вкладки, экраны, блоки на экранах,
   тексты, набор сущностей и правила синхронизации описаны в `config/*.json`. Тот же
   формат отдаётся сервером (`GET /app-config`), поэтому новый клиент сети или новая
   раскладка главной не требуют релиза в сторах.
2. **Offline-first на SQLite.** Схема БД генерируется из конфигурации сущностей;
   приложение читает только из локальной базы, поэтому работает без сети.
3. **Синхронизация по API.** Дельта-загрузка по курсору `updated_at` и очередь
   исходящих изменений (`_outbox`) с экспоненциальными повторами.

## Стек

| Слой | Технология |
|------|------------|
| UI | React Native 0.8x + Expo SDK 57, TypeScript (strict) |
| Навигация | React Navigation (табы собираются из JSON) |
| Локальная БД | SQLite: `expo-sqlite` на устройстве, `node:sqlite` в тестах и CLI |
| Сеть | `fetch` + собственный клиент: таймауты, повторы, Bearer-токен, refresh на 401 |
| Авторизация | Вход по коду из SMS или по паролю (задаётся конфигурацией), токен — в keychain/keystore через `expo-secure-store` |
| Камера и push | `expo-camera` (сканер штрихкодов), `expo-notifications` (уведомления и переходы по ним) |
| Тесты | Jest + ts-jest, 148 тестов (конфигурация, БД, синхронизация, авторизация, корзина и заказы, купоны, push, домен, e2e против mock-сервера) |

## Требования

- Node.js 22+ (тесты и CLI используют встроенный модуль `node:sqlite`);
- Expo Go либо симулятор iOS / эмулятор Android для запуска приложения.

## Быстрый старт

```bash
cd mobile
npm install

# 1. Локальный «бэкенд» с демо-данными (26 товаров, 12 категорий, 2 каталога акций, 4 магазина)
npm run start:mock          # http://localhost:4000

# 2. Приложение (Expo Go / симулятор)
npm start
```

Приложение в dev-режиме берёт адрес API из `app.json` → `expo.extra.apiBaseUrl`
(по умолчанию `https://api.una.md/retail/v1`; для работы с моком укажите
`http://localhost:4000`). Значение из dev-сборки всегда важнее того, что приходит
с сервера.

## Проверки

```bash
npm run typecheck        # tsc --noEmit
npm run validate-config  # валидация JSON-конфигурации (используйте в CI перед публикацией конфига)
npm test                 # jest
npm run check            # всё вместе
```

`npm run validate-config` проверяет не только синтаксис: что каждая вкладка ссылается
на существующий экран, каждый блок — на известный тип, каждый запрос — на существующие
поля сущности, что ключи переводов есть во всех локалях и что цвета темы объявлены и в
светлой, и в тёмной схеме.

```
mobile/

│   ├── navigation.config.json # вкладки и их порядок

│   ├── screens/*.json         # экраны как списки блоков (server-driven UI)
│   └── l10n/{ro,ru,en}.json   # переводы
├── src/
│   ├── config/                # типы, валидатор, слияние удалённой конфигурации
│   ├── auth/                  # вход, хранение сессии, выход и очистка данных аккаунта
│   ├── push/                  # регистрация токена и переходы по уведомлениям
│   ├── db/                    # драйверы SQLite, миграции, репозитории, outbox, query builder
│   ├── api/                   # HTTP-клиент
│   ├── sync/                  # движок синхронизации (pull/push)
│   ├── domain/                # цены, штрихкоды, список покупок, часы работы магазинов
│   ├── state/                 # React-контексты и хуки данных
│   ├── ui/                    # блоки, компоненты, экраны, навигация
│   └── bootstrap.ts           # старт приложения
├── tools/                     # mock-сервер, валидатор конфигурации, демо-данные
├── docs/                      # архитектура, контракт API, руководство по конфигурации
└── __tests__/                 # тесты
```

## Покупки: корзина, заказы, купоны

- **Корзина** живёт только на устройстве (`cart_items` — сущность с
  `direction: "local"`, она никогда не уходит на сервер): корзина принадлежит телефону,
  на котором её собрали.
- **Оформление заказа** — самовывоз или доставка (набор способов, минимальная сумма,
  стоимость доставки, порог бесплатной и интервалы — из конфигурации). Заказ пишется
  локально и уходит через очередь, поэтому оформить его можно и без сети: сервер
  присвоит номер и подтвердит, когда связь появится.
- **Заказы** синхронизируются в обе стороны: статусы приходят с сервера, отмена
  уходит на сервер. Экран заказа показывает прогресс (новый → подтверждён → собирается
  → готов/в доставке → выполнен), состав и кнопку «повторить заказ».
- **Купоны** — персональные, с процентной или суммовой скидкой, ограничением по
  товарам/категориям и минимальной суммой. Активация уходит на сервер пачкой (batch),
  применение к корзине пересчитывает итог и влияет на бесплатную доставку.

## Push-уведомления и сканер

- **Push**: токен регистрируется молча (разрешение спрашивается в контексте — после
  входа или из настроек, не на первом запуске), повторная отправка токена не делается,
  пока не изменились токен, пользователь или язык. При выходе из аккаунта токен
  отзывается. Нажатие на уведомление открывает нужный экран — маршрут берётся из
  полезной нагрузки, но только из белого списка экранов и только строковые параметры.
- **Сканер**: камера ищет товар по штрихкоду в локальной базе (работает в зале без
  связи), понимает EAN-13/EAN-8/UPC-A/Code 128/QR и эквивалентные формы кода. По
  конфигурации либо открывает карточку товара, либо сразу кладёт его в список покупок.

## Личный кабинет

- **Вход по коду из SMS** (`api.auth.flow: "otp"`) либо по логину и паролю
  (`"password"`) — переключается в конфигурации, экран один и тот же.
- **Сессия** хранится в keychain/keystore (`expo-secure-store`), с откатом на локальную
  базу там, где хранилища нет (веб, часть эмуляторов). Токен добавляется к запросам
  автоматически, на `401` один раз выполняется refresh.
- **Профиль** — двусторонняя сущность: правки сохраняются локально и уезжают на сервер
  через очередь, поэтому редактирование работает и без сети.
- **История покупок и электронные чеки** — список чеков, детализация по позициям,
  скидки, баллы, фискальный код штрихкодом и кнопка «добавить всё в список покупок».
- **Выход** удаляет с устройства всё, что относится к аккаунту (карта, чеки, профиль,
  избранное) и их очереди; список покупок — данные устройства, он остаётся.

Демо-вход против mock-сервера: любой корректный номер, код `1234` (сервер возвращает
его в поле `dev_code`).

## Границы текущей версии

- Онлайн-оплаты нет: при оформлении выбирается оплата наличными или картой при
  получении. Платёжный провайдер (например, maib) подключается отдельным шагом.
- Регистрация и восстановление пароля для `flow: "password"` не реализованы — в Молдове
  сценарий закрывает вход по SMS.
- Push требует dev-сборки: в Expo Go на Android токен не выдаётся (приложение это
  переживает — просто не регистрирует токен).
- Иконки — юникодные глифы в `src/ui/components/Icon.tsx`; при желании заменяются на
  `@expo/vector-icons` в одном файле.
