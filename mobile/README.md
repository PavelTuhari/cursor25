# UNA Market — мобильное приложение для платформы UNA.md

Кросс-платформенное (iOS + Android) розничное приложение в стиле Kaufland / Auchan:
каталог, акции и каталоги-листовки, карта лояльности со штрихкодом, список покупок,
магазины и поиск.

Три принципа заложены в архитектуру:

1. **Всё конфигурируется через JSON.** Бренд, тема, вкладки, экраны, блоки на экранах,
   тексты, набор сущностей и правила синхронизации описаны в `config/*.json`. Тот же
   формат отдаётся сервером (`GET /app-config`), поэтому новый клиент сети или новая
   раскладка главной не требуют релиза в сторах.
2. **Offline-first на SQLite.** Схема БД генерируется из конфигурации сущностей;
   приложение читает только из локальной базы, поэтому работает без сети.
3. **Синхронизация по API.** Дельта-загрузка по курсору `updated_at` и очередь
   исходящих изменений (`_outbox`) с экспоненциальными повторами.

## Стек

| Слой | Технология |
|------|------------|
| UI | React Native 0.8x + Expo SDK 57, TypeScript (strict) |
| Навигация | React Navigation (табы собираются из JSON) |
| Локальная БД | SQLite: `expo-sqlite` на устройстве, `node:sqlite` в тестах и CLI |
| Сеть | `fetch` + собственный клиент: таймауты, повторы, Bearer-токен, refresh на 401 |
| Тесты | Jest + ts-jest, 89 тестов (конфигурация, БД, синхронизация, домен, e2e против mock-сервера) |

## Требования

- Node.js 22+ (тесты и CLI используют встроенный модуль `node:sqlite`);
- Expo Go либо симулятор iOS / эмулятор Android для запуска приложения.

## Быстрый старт

```bash
cd mobile
npm install

# 1. Локальный «бэкенд» с демо-данными (26 товаров, 12 категорий, 2 каталога акций, 4 магазина)
npm run start:mock          # http://localhost:4000

# 2. Приложение (Expo Go / симулятор)
npm start
```

Приложение в dev-режиме берёт адрес API из `app.json` → `expo.extra.apiBaseUrl`
(по умолчанию `https://api.una.md/retail/v1`; для работы с моком укажите
`http://localhost:4000`). Значение из dev-сборки всегда важнее того, что приходит
с сервера.

## Проверки

```bash
npm run typecheck        # tsc --noEmit
npm run validate-config  # валидация JSON-конфигурации (используйте в CI перед публикацией конфига)
npm test                 # jest
npm run check            # всё вместе
```

`npm run validate-config` проверяет не только синтаксис: что каждая вкладка ссылается
на существующий экран, каждый блок — на известный тип, каждый запрос — на существующие
поля сущности, что ключи переводов есть во всех локалях и что цвета темы объявлены и в
светлой, и в тёмной схеме.

## Структура

```
mobile/
├── config/                    # ← вся конфигурация приложения
│   ├── app.config.json        # бренд, валюта, API, синхронизация, фич-флаги
│   ├── theme.config.json      # цвета (light/dark), типографика, отступы, радиусы
│   ├── navigation.config.json # вкладки и их порядок
│   ├── entities.config.json   # модель данных = схема SQLite + правила синхронизации
│   ├── screens/*.json         # экраны как списки блоков (server-driven UI)
│   └── l10n/{ro,ru,en}.json   # переводы
├── src/
│   ├── config/                # типы, валидатор, слияние удалённой конфигурации
│   ├── db/                    # драйверы SQLite, миграции, репозитории, outbox, query builder
│   ├── api/                   # HTTP-клиент
│   ├── sync/                  # движок синхронизации (pull/push)
│   ├── domain/                # цены, штрихкоды, список покупок, часы работы магазинов
│   ├── state/                 # React-контексты и хуки данных
│   ├── ui/                    # блоки, компоненты, экраны, навигация
│   └── bootstrap.ts           # старт приложения
├── tools/                     # mock-сервер, валидатор конфигурации, демо-данные
├── docs/                      # архитектура, контракт API, руководство по конфигурации
└── __tests__/                 # тесты
```

## Что можно изменить без релиза

| Задача | Файл / место |
|--------|--------------|
| Логотип, название, валюта, телефон поддержки | `config/app.config.json` → `app` |
| Фирменные цвета, тёмная тема, скругления | `config/theme.config.json` |
| Включить/выключить лояльность, список, магазины, акции | `config/app.config.json` → `features` |
| Порядок и состав вкладок | `config/navigation.config.json` |
| Раскладка главной, новые секции с товарами | `config/screens/home.json` |
| Новое поле товара (например, «цена по карте») | `config/entities.config.json` → миграция выполнится автоматически |
| Тексты и новый язык | `config/l10n/*.json` |
| Адрес API, размер страницы, интервал синхронизации | `config/app.config.json` → `api`, `sync` |

Подробности — в [docs/configuration.md](docs/configuration.md).
Контракт бэкенда — в [docs/api-contract.md](docs/api-contract.md).
Как всё устроено внутри — в [docs/architecture.md](docs/architecture.md).

## Что ещё не сделано

- Экран авторизации и получение токена (`api.auth.loginEndpoint` уже описан в конфигурации,
  клиент умеет Bearer и refresh на 401; сам UI входа не реализован).
- Push-уведомления, персональные купоны, корзина и онлайн-заказы — фич-флаги
  (`cart`, `onlineOrders`) выключены и соответствующие блоки не реализованы.
- Токен хранится в таблице `_kv`; для продакшена его следует перенести в
  `expo-secure-store` (см. `src/bootstrap.ts`).
- Иконки — юникодные глифы в `src/ui/components/Icon.tsx`; при желании заменяются на
  `@expo/vector-icons` в одном файле.
