# Локальная разработка

[← к оглавлению](INDEX.md)

Весь стек поднимается без Oracle, без доступа к SFS и без сертификатов. Оба
эмулятора реализуют те же контракты, что и настоящие системы, поэтому
разрабатывать и тестировать можно до того, как выданы учётные данные.

## Требования

| | Зачем |
|---|---|
| **Node.js 22+** | приложение и микросервис; тесты используют встроенный `node:sqlite` |
| Expo Go, симулятор iOS или эмулятор Android | запуск приложения на устройстве |
| Браузер | режим Expo Web, если устройства нет |

Oracle, Instant Client, сертификаты и учётные данные SFS для локальной работы
**не нужны**.

## Пять команд

```bash
# 1. Микросервис: эмулятор SFS
cd efactura-service && npm install && npm run start:mock-sfs
```

```bash
# 2. Микросервис: сам сервис, в памяти, против эмулятора
cd efactura-service && EFACT__ORACLE__CONNECTSTRING=memory \
  EFACT__SFS__ENDPOINT=http://127.0.0.1:4010/Service.svc \
  EFACT__SFS__USERNAME=supplier EFACT__SFS__PASSWORD=supplier \
  npm run dev
```

```bash
# 3. Приложение: эмулятор бэкенда UNA.md
cd mobile && npm install && npm run start:mock
```

```bash
# 4. Приложение
cd mobile && npm start
```

Приложение берёт адрес API из `app.json` → `expo.extra.apiBaseUrl`. Для работы с
моком укажите там `http://localhost:4000`. Значение из dev-сборки всегда важнее
того, что приходит с сервера.

## Порты

| Порт | Что |
|---|---|
| 4000 | mock UNA.md API |
| 4010 | mock SIA e-Factura (SOAP) |
| 8081 | Expo dev server |
| 8090 | микросервис e-Factura |

## Демо-данные

**Приложение** — 26 товаров, 12 категорий, 2 каталога акций, 4 магазина,
6 чеков, одна компания и три фактуры в разных состояниях. Вход: любой корректный
номер, код `1234` (мок возвращает его в поле `dev_code`).

**Микросервис** — реестр из трёх контрагентов, выдача серий начиная с `EAA
000005001`. Эмулятор **проводит фактуру по реальному жизненному циклу**:
подписанная становится «отправлена покупателю», затем «принята покупателем», так
что опрос статусов есть что показывать.

## Проверка сквозного сценария

```bash
curl -s -X POST http://127.0.0.1:8090/efactura/v1/invoices \
  -H 'Content-Type: application/json' \
  -d @efactura-service/docs/example-invoice.json

curl -s -X POST http://127.0.0.1:8090/efactura/v1/tick

curl -s http://127.0.0.1:8090/efactura/v1/invoices/DOC-1001
curl -s http://127.0.0.1:8090/efactura/v1/invoices/DOC-1001/qr
curl -s http://127.0.0.1:8090/efactura/v1/taxpayers/1000000000033
```

`POST /tick` прогоняет очередь немедленно, не дожидаясь таймера.

## Превью-окна

Отдельное внутреннее окно, где один экран открывается **сразу в нужном
состоянии**, минуя вход, синхронизацию и навигацию.

```
http://localhost:8081/?preview=wallet&scenario=default
```

| Сценарий | Что показывает |
|---|---|
| `default` | подключённая компания, входящие от двух поставщиков, одна фактура наполовину оплачена |
| `empty` | ничего не подключено — то, что видит новый корпоративный клиент |
| `invalid` | учётные данные отклонены налоговой; чинит только владелец |
| `sending` | решение принято офлайн и стоит в очереди |
| `rejected` | отклонённая фактура с причиной |

Устроено так, чтобы результату можно было верить:

* работают **настоящие** блоки, настоящая конфигурация и настоящий слой базы —
  фиксированы только данные, поэтому ошибка в экране здесь видна;
* открывается **своя** база `wallet-preview.db` — посев не трогает данные
  приложения и не сбивается синхронизацией;
* сценарий берётся **из URL**, поэтому окно гоняется без единого клика, что и
  делает его пригодным для проверки из тест-раннера.

Включается только в dev-сборке и только явно: `?preview=wallet` на вебе либо
`expo.extra.preview` в конфигурации. В релизной сборке код недостижим —
`__DEV__` там ложь.

Добавить окно для другого экрана: сценарии в
[`src/dev/walletScenarios.ts`](../mobile/src/dev/walletScenarios.ts) по образцу,
рендер — в [`src/dev/WalletPreview.tsx`](../mobile/src/dev/WalletPreview.tsx),
и ветка в `requestedPreview()` в `App.tsx`.

> Оговорка про Metro: он не всегда подхватывает **новые** файлы и изменения в
> `config/*.json`. Если окно показывает старое состояние — перезапустите
> `expo start --web --clear`.

## Проверки перед коммитом

```bash
cd mobile           && npm run check   # typecheck + валидация конфигурации + 160 тестов
cd efactura-service && npm run check   # typecheck + валидация конфигурации +  89 тестов
```

`validate-config` в приложении проверяет не только синтаксис: что каждая вкладка
ссылается на существующий экран, каждый блок — на известный тип, каждый запрос —
на существующие поля сущности, что ключи переводов есть во всех локалях и что
цвета темы объявлены и в светлой, и в тёмной схеме.

`validate-config` в микросервисе печатает применённые переменные окружения и
**предупреждает об опечатках**: `EFACT__SFS__USERNMAE` не будет молча
проигнорирован.

## Работа с настоящей SFS

Когда CTIF выдаст доступ:

```bash
EFACT__SFS__ENDPOINT=https://efactura-api.sfs.md/Service.svc \
EFACT__SFS__USERNAME=<API-пользователь> \
EFACT__SFS__PASSWORD=<пароль> \
npm run dev
```

Самая полезная первая проба — `GET /taxpayers/{idno}`: она разом проверяет сеть,
TLS, учётные данные и разбор ответа.

API-пользователь создаётся **директором компании** в кабинете e-Factura:
Настройки → Пользователи компании → «Înregistrează un utilizator API». Это не
логин директора.

## Работа с настоящим Oracle

```bash
cd efactura-service
EFACT__ORACLE__CONNECTSTRING=host:1521/PDB \
EFACT__ORACLE__USER=EFACTURA EFACT__ORACLE__PASSWORD=... \
npm run migrate
```

Мигратор применяет пронумерованные файлы из `sql/`, пропуская уже применённые.
Вьюшки на ERP (`002_erp_views.sql`) по умолчанию не применяются — они
принадлежат владельцу учётной схемы, см.
[DEPLOY.md](../efactura-service/docs/DEPLOY.md).

## Известные особенности окружения

**Expo Web.** Веб-режим требует `react-native-web`, `@expo/metro-runtime` и
`metro.config.js`, который добавляет `.wasm` в `assetExts` и отдаёт заголовки
COOP/COEP — иначе `expo-sqlite` виснет на бесконечном спиннере. Всё это уже
настроено в репозитории.

**Картинки в демо-данных** ссылаются на `https://cdn.una.md`, которого не
существует: карточки рисуются без изображений. На логику не влияет.

**Windows.** `npm` 11 блокирует install-скрипты; для `esbuild` (нужен `tsx`) и
`oracledb` они разрешены через поле `allowScripts` в `package.json`.
