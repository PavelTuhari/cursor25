## Организации

| Сокращение | Расшифровка | Что делает |
|---|---|---|
| **SFS** | Serviciul Fiscal de Stat | Государственная налоговая служба Молдовы; владелец системы e-Factura |
| **CTIF** | Centrul de Tehnologii Informaționale în Finanțe | оператор системы, автор руководств по интеграции; поддержка **022 822222** |
| **STISC** | Serviciul Tehnologia Informației și Securitate Cibernetică | сервис автоматической подписи PKI-Server; поддержка **022 820911** |

## Система e-Factura

| Термин | Значение |
|---|---|
| **SIA «e-Factura»** | Sistem Informațional Automatizat — государственная система создания и оборота электронных фискальных фактур |
| **ETI** | Electronic Tax Invoice, factura fiscală electronică — электронная фискальная фактура |
| **НН** | налоговая накладная — то же, что ETI и factura fiscală; принятое в русскоязычном обиходе Молдовы обозначение |
| **EW** | Electronic Waybill, scrisoare de trăsătură — электронная накладная; `InvoiceType: 1` |
| **Semi automatizat** | режим, где фактура создаётся в учётной системе, а подписывается вручную в кабинете |
| **Complet automatizat** | режим, где учётная система подписывает и отправляет сама, не заходя в кабинет; **этот сервис работает так** |
| **Serie и număr** | серия и номер фактуры; резервируются в SFS заранее через `GetSeriaAndNumbers` |
| **Actor** | участник сделки: поставщик (1), покупатель (2), перевозчик (3) |
| **CreationMotiv** | причина создания документа; 4 — обычная продажа |
| **IsFarma** | признак фармацевтической продукции |

## Идентификаторы

| Термин | Значение |
|---|---|
| **IDNO** | Identificator Unic de Stat al Organizației — 13 цифр, идентификатор юрлица |
| **IDNP** | Numărul de Identificare Personal — 13 цифр, идентификатор физлица |
| **Cod TVA** | код плательщика НДС, 6–8 цифр; есть не у всех — компания ниже порога не регистрируется |
| **TVA** | Taxa pe Valoarea Adăugată — НДС; в Молдове стандартная ставка 20%, льготные 8% и 0% |
| **IBAN** | в Молдове: `MD` + 2 контрольные цифры + 20 символов |
| **Bon fiscal** | кассовый чек; для вычета НДС юрлицу его недостаточно — нужна фактура |

## Технические

| Термин | Значение |
|---|---|
| **WCF** | Windows Communication Foundation — на нём написан API e-Factura |
| **BasicHttpBinding** | SOAP 1.1 поверх HTTP; используемый binding |
| **TransportWithMessageCredential** | TLS защищает канал, а вызывающего идентифицирует `UsernameToken` в заголовке |
| **UsernameToken** | элемент WS-Security с именем и паролем; здесь — `PasswordText`, то есть открытым текстом под TLS |
| **DataContract** | сериализация WCF; **порядок элементов фиксирован** — сначала члены базового типа, потом свои, каждая группа по алфавиту |
| **XMLDSig** | XML Signature; стандарт подписи, применяемый в e-Factura |
| **Exclusive C14N** | каноническая форма XML перед хешированием и подписью |
| **XAdES** | расширение XMLDSig с меткой времени; в примерах гайда не используется |
| **PKCS#12** | контейнер `.p12`/`.pfx` с закрытым ключом и сертификатом |
| **PKI-Server** | сервис STISC, подписывающий в HSM; ключ не покидает хранилище |
| **MPass / MSign** | государственные сервисы аутентификации и подписи Молдовы; в этом API не задействованы |

## Термины проекта

| Термин | Значение |
|---|---|
| **Outbox** | таблица `EFACT_OUTBOX` (и `_outbox` в приложении) — очередь исходящих; гарантирует доставку без дубликатов |
| **Tenant** | клиент сети; `service.tenantId` разделяет данные, если одна установка обслуживает нескольких |
| **Thin-режим** | node-oracledb без Instant Client, на чистом JavaScript |
| **Блок** | единица экрана в приложении: запись в JSON с `type` и `props`, отображаемая в React-компонент |
| **Server-driven UI** | раскладка экранов приходит с сервера в JSON и меняется без релиза в сторах |
| **Дельта-синхронизация** | загрузка только изменений по курсору `updated_at` |
| **`externalId`** | идентификатор документа в учётной системе; уникален в пределах tenant и делает отправку идемпотентной |

## Состояния

**Очередь микросервиса** (`state`):

| Значение | Смысл |
|---|---|
| `pending` | принят, ещё не обработан |
| `reserved` | назначены серия и номер |
| `built` | XML сформирован |
| `signed` | подписан |
| `posted` | отправлен в SFS |
| `confirmed` | достиг терминального статуса в e-Factura |
| `canceled` | отозван поставщиком или отклонён покупателем |
| `failed` | неустранимая ошибка либо исчерпаны попытки |

**Статус в e-Factura** (`InvoiceStatus`): 0 черновик · 1 подписана поставщиком ·
2 отклонена покупателем · 3 принята покупателем · 5 отозвана поставщиком ·
7 отправлена покупателю · 8 подписана покупателем · 10 доставлена.

**Статус ответа API** (`Status` в любом ответе SFS): 1 принят к исполнению ·
2 выполнен · 3 ошибка.
